# Candidate release checklist

- [x] Consistent slug/textdomain/version 0.1.0.
- [x] Distribution built from an explicit allowlist.
- [x] No master/private photo/runtime dependency in distribution.
- [x] Master and output SHA checks, bounded inputs and ownership cleanup.
- [x] Central engine for manual/automatic/batch work.
- [x] POST, capabilities, nonces, escaping and scope-limited assets.
- [x] No frontend asset, telemetry, public API or external optimization call.
- [x] Local real WordPress integration and browser tests.
- [x] Crash, lock, orientation, quantization and concurrency tests.
- [ ] Human benchmark and administrator visual acceptance.
- [ ] Real Imagick, MySQL/MariaDB, Linux permissions, multisite certification.
- [ ] Real coexistence with selected commercial optimizers.
- [ ] Production deployment authorization.
- [ ] GitHub publication, tag/release or WordPress.org submission.

Unexecuted environments must remain unexecuted in the compatibility report.
READY FOR HUMAN PASS is not PRODUCTION READY.
